# Practical controls, not guaranteed outcomes

Scope the task, identify relevant files, review a plan, approve permitted actions,
inspect diffs, and run validation. Instructions are guidance, not an enforcement
boundary. Use real permissions and isolated worktrees. No allow-all/autopilot
permission setting is required for a workshop.

Show surfaced files/tools/approvals/errors/results; this is not a complete audit
trail or disclosure of all context/internal reasoning. Record observability gaps
instead of claiming every action is visible.

Context tokens, session usage, account billing, enterprise adoption, and business
value are different measurements. Verify installed context/usage views and
current account billing regime; do not hardcode prices, allowances, savings, or
cross-surface cost parity. Focused context helps scope, not guaranteed cost.
Inspect AI-credit/budget/enforcement settings with an authorized administrator;
an alert or local soft limit is not necessarily an enforced tenant spending cap.
Agent/review runs can incur applicable metered and Actions usage.

Reporting questions: who is active, on which surfaces, which workflows recur,
what report period/latency applies, which model/retries/actions drive usage,
which budgets actually block spend, and what outcome demonstrates value?
Use approved sanitized evidence or explicitly state access/data is unavailable.
No usage/billing API, production telemetry backend, or tenant change is included.

For production agents, discover users, inputs, outputs, actions, errors, latency,
permissions, retention and cost drivers. For SharePoint, discover access,
freshness, representative questions, grounding/evaluation and failure behavior.
Do not recommend Foundry migration, orchestration, routing, throughput,
Copilot Studio redesign, ingestion, or tenant consolidation from this local demo.
